01 / PROJECT

為什麼做「天空之眼」？

災害發生後，第一時間掌握現場資訊本身就是重要的救援能力。

專案從災害現場難以快速掌握災情的問題出發。傳統逐區排查需要時間， 也可能讓救援人員暴露在危險環境中，因此嘗試以無人機進行空中勘查， 再由程式分析災前與災後影像。

系統希望回答三個核心問題：哪裡可能受損？哪裡可能有人？ 在目前影像條件下，可以提供哪些避難資訊？

02 / SYSTEM FLOW

系統如何運作？

依照提供的專題講稿與流程簡報整理成六個展示階段。

01

無人機影像取得

使用搭載鏡頭的無人機取得現場影像，並回傳至電腦進行後續處理。

02

影像配準

先處理不同拍攝角度、高度與位置造成的偏移，再進行災前／災後比較。

03

災區受損偵測

分析影像差異並進行形態學處理與區域篩選，將可能受損區域標示出來。

04

人員偵測

使用 OpenCV HOG 人員偵測器尋找可能的人員位置，作為後續規劃依據。

05

避難規劃

避開災損區域，產生候選避難點，並計算人員與避難點的距離。

06

雲端與 LINE Bot

將分析資訊與圖片透過雲端、伺服器及 LINE Bot 傳送給使用者。

影像配準

完整程式碼版本使用 ORB 特徵點、BFMatcher 與 Homography / RANSAC 將兩張影像對齊，再進行後續分析。

災損偵測

提供的完整 Python 程式碼目前實際執行的是 HSV 影像差異、閾值化、 形態學開／閉運算，以及連通元件面積篩選；講稿則描述曾進一步研究 結構相似度方法。網站因此將兩者分開標示，避免把研究敘述誤寫成目前程式的實際實作。

04 / PEOPLE & EVACUATION

找到可能受損的地方，也關注「人在哪裡」

01

人員偵測

程式中的 detect_people() 使用 OpenCV HOG 預設人員偵測器，取得偵測框中心點。

02

候選避難點

generate_safe_points() 會排除災損遮罩與綠色區域，並限制候選點彼此的最小距離。

03

最近避難點

系統計算每個人與候選避難點的距離，找出最近的候選點並建立連線。

04

風險程度

目前程式依災損比例與偵測人數以規則判定「低／中／高／極高」，屬於專案原型的分析規則。

06 / DEVELOPMENT

真正重要的是「怎麼改進」

01

先讓系統跑起來

建立無人機取像、影像讀取與基本分析流程。

02

發現影像不能直接比較

不同角度、高度與拍攝位置會造成影像偏移，因此加入影像配準。

03

處理災損誤判

針對光線、陰影與雜訊造成的差異，逐步加入影像處理與區域篩選。

04

從災損走向人的位置

加入人員偵測與避難點規劃，使分析結果更接近使用情境。

05

把結果送到手機

整合雲端、伺服器與 LINE Bot，完成從拍攝、分析到通報的展示流程。

07 / LIMITATIONS

研究限制與下一步

目前網站以提供的專題講稿、流程簡報與完整 Python 程式碼為基礎。災後情境部分使用模擬資料；系統中的人員偵測、避難點與風險規則也屬原型實作，因此不應視為實際災害現場的官方判定。

Future

紅外線／熱影像、Edge AI、降低網路依賴、更完整的 GIS 與道路網路分析，皆可作為後續研究方向。
